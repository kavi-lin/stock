## 2. 觀察到的 Patterns

### Pattern A: extractor 讀簡報層而非資料層，跨兩個獨立 source 各自造成缺值與錯值 [N=12/74 + 6/15，信心: 高]

- **觀察（news-digest 側）**：`session_macro_delta` 是 `news/digest_output_schema.md:45` 的必填欄，
  值確實存在於 `news/news_logs/<date>_digest.json`，但 `news_digest_extractor.py` 以 regex 刮 MD 報告。
  2026-08-06 起 MD header 改版（`**Mode**: DIGEST ｜ **Generated**: … ｜ **Stage 1** ｜ **Stage 2** ｜ **Fan-out**）
  不再複述該欄 → 連續 3 次 run（08-06 / 08-07 / 08-10）全 null，而 JSON 內分別為 −0.1 / −0.75 / +0.3。
  7 筆 null **7/7 可回收**；另 5 筆 scraped 值與權威值不符（最大偏差 04-14：−0.3 vs −1.2）。
- **觀察（deep-dive 側）**：權威 `hot_zone_eval` 可比列由 10 增至 **15**，mismatch **6/15 (40%)**。
  4 筆非平凡狀態（`suppressed_by_cap`×3、`fired`×1）**4/4** 被 shadow 錯分；
  新增證據：NET 08-07 權威 `suppressed_by_cap` vs shadow `not_qualifying`、
  AAOI 08-07 與 META 08-10 權威 `not_qualifying` vs shadow `qualifying_unexplained`。
  index 的 `hot_zone_probe` / `hot_zone_eval` 仍 **0/175**，而 history.json 已有 48 / 18 筆非 null。
- **root cause 假設 1（高信心）**：單一結構性缺陷 —— `scripts/build_event_index.py` 全檔不開啟任何
  權威 JSON export，所有 decision_content 欄位一律由 MD 文字反推。凡「權威值只存在於 JSON、MD 未複述」
  的欄位必然 null 或錯值，且**缺陷隨 MD 模板改版而隨機發作**（news header 改版即為觸發事件）。
  兩個互不相干的 source 各自獨立呈現同一失效模式 → 非個別 parser bug。
- **root cause 假設 2（中信心）**：驗收判準錯誤放行 —— TODO-015 當初以 `hot_zone_eval_derived` 覆蓋率
  164/164 驗收，但 derived 是對 MD 的反推、必然 100%，對「權威值有沒有進 index」零資訊量。
  Rec 4 同理以 null_rate 驗收而未做權威值一致性比對，故 5 筆 scraped 錯值 4 個月未被發現。
- **需要哪些額外資料**：join 落地後跑權威 vs scraped 一致性計數器；對其餘 source
  （thematic-screener / sector-scan 皆有 JSON 產物）做同樣比對，確認缺陷範圍。
