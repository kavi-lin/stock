# 事件研究重設計：六小時結論報告

**實作、測試與六小時觀察已完成；結果為 `complete_with_gaps`。** 新機制已把辯論轉成各分頁可讀的研究卡，Broker 可逐次追蹤呼叫與結算。資料流與對帳通過；本輪仍不足以證明研究品質或節省成本已達長期上線標準。

觀察窗：台灣時間 **2026-10-05 02:07:31–08:07:31**；程序於 08:07:42 自動結束。正式 28 次呼叫、15 次辯論嘗試，其中 13 組完整 A/B，產出 19 張卡。60 次呼叫／30 次辯論是上限，沒有補造事件湊滿。最後 42 分 50 秒因供應商 quota 錯誤停止推論，取材與觀察持續至截止。

## 1. 已完成的機制

```text
Before
RSS / Futu / social
        |
    新聞門檻 -> 多輪立場辯論 -> 整體 verdict -> 候選訊號

After
RSS / FMP / Finnhub / SEC / IR / macro
        |                       calendar / followup
        |                              |
    去重、來源健康、公司解析 <--- 新發布且有新增證據
        |
    事件 + 證據版本 -> 重要性門檻
        |
    Broker reserve/start -> Luna/max A -> Luna/max B
        |                       |
        |                原文引證與逐項審查
        |                       |
    用量、結果持久保存 -> Broker complete ACK
                                |
                   主張 / 不確定性 / 反證 / 追蹤條件
                                |
               個股 / 財報 / 動能 / 事件研究 / Nexus候選
```

新聞仍是主要入口，但排程到期、追蹤到期只有在匹配到新證據時才可觸發推論。公司識別沿用公開股票範圍與公司別名，無持倉或 watchlist 依賴。來源提供的 ticker 提示與文字識別分開，避免供應商誤標直接觸發研究。

六個頁面已接共用研究面板；個股可看指定 ticker、上次分析後最多三項變化，保留原文、來源摘要／網頁區別、發布時間及追蹤條件。Nexus 僅提供 provisional 候選。研究卡皆標記 exploratory，不輸入正式 buy_threshold、position_size、verdict。

Broker 增加四種 task type：`research-initial-analysis`、`research-initial-challenge`、`research-recheck-analysis`、`research-recheck-challenge`，category 為 `ensemble`。每筆附 experiment、phase、event、revision、debate、trigger、stage、effort；schema v8 支援冪等結算與晚到用量，查詢先依 metadata 過濾再分頁。

兩筆未知分別為初次正式呼叫的 native schema 拒絕，以及最後一筆 quota 錯誤。兩筆都已向 Broker 結算為未知，沒有補零或重新呼叫。初測首例因舊版帳本結算失敗，修復 v8 後精確補送；其原始分析回覆未保存、沒有 B 階段，明列限制，不能把 12 個合成案例稱為 12 組完整 A/B。

## 3. 研究卡有沒有用

19 張卡來自 13 個事件：11 fact、7 question、1 inference；14 supported、5 insufficient，沒有 contested／retracted。`supported` 指給定證據支持該段表述，並非外部世界已被獨立證實。七張 question 中也有以「摘錄不足以回答」為主張而獲 supported 的情形，應連同種類閱讀。

| 案例 | 可供分頁使用的資訊 | 仍缺少什麼 |
|---|---|---|
| PTC 收購報導 | 將交易傳聞與已完成交易分開；追蹤公司公告或否認 | 公司正式證實、條款、完成條件 |
| AKZOY 出售業務報導 | 保留「可能出售」及媒體轉述關係 | 正式協議與原始公司文件 |
| FLXS 利潤率標題 | 明列 8% 的期間、口徑及是否正式指引尚不清楚 | 公司簡報或申報文件 |
| 油價與設施遇襲 | 將來源報導的價格變動與因果推論分開 | 設施運作、產出與出口是否中斷 |
| 早期低增量新聞 | 保留週報預覽、一般政治、個人薦股等原始失敗樣本 | 這些樣本的研究效益偏低；已補篩選門檻 |

**來源深度是目前最大限制。** 17／19 張卡的證據包只有 feed 摘錄；另兩張的證據包包含同一事件的原始新聞網頁。若依「主張實際引用的 evidence ID」計算，只有 **1／19 張直接引用原始網頁、18／19 張只引用 feed**。原始新聞網頁仍不是公司第一手公告。這兩種分母在最終稽核中分開，避免把「抓到網頁」當成「主張已使用網頁證據」。

本輪實際觸發全為 news；filing、calendar、followup 的真實樣本均為 0，只由合成案例與確定性測試覆蓋。早期 Micron、FedEx 名稱未正確映射的卡保留原樣；後續加入摘要與既有別名解析。以上修正在同一觀察窗內完成，因此本輪是探索與故障修復觀察，並非凍結版本的受控 A/B 品質實驗。

## 4. 來源與可靠性

六小時共完成 **32 次取材**。表內次數是每輪來源觀測，不能當作不重複文章量。

| 來源群 | 本輪結果 | 判斷 |
|---|---|---|
| FMP／Finnhub、主要市場 RSS | FMP／Finnhub 各 32 次成功；有真實新事件 | 可保留作發現入口，ticker tag 仍需驗證 |
| SEC EDGAR／BEA／NVIDIA IR | 連線或條件式回覆正常，沒有符合窗口的新正式發布 | 保留優先權；本輪無法評價其事件研究品質 |
| BLS CPI／Employment | 各 4 次錯誤、28 次退避；HTTP 403 | 視為不可用，不能把空集合說成沒有發布 |
| Futu／Social | Futu 30 次錯誤、2 次成功但無項目；Social 31 次降級、1 次錯誤 | 僅作補充發現；已隔離逾時，不拖住主來源 |
| Fed Press | 曾一次錯誤及一次退避，後續恢復 | 健康狀態應呈現整段歷史，不能只看最後一輪 |

初期 Futu 本機目錄掃描阻塞，造成 **453.4 秒心跳間隔**；改為獨立程序、Futu 15 秒／Social 90 秒上限。這是中斷指標，不能推算成確切漏掉多少新聞。

Broker 忙碌共等待後恢復兩次，合計 **577.6 秒**；只以唯讀狀態確認空閒後重申請，沒有用模型呼叫探測。最後 quota 錯誤發生於 07:24:41，之後沒有新推論。每個階段都檢查截止時間；收尾稽核確認滾動一小時最多 5 次辯論，截止後呼叫 0，worker 已退出。

## 5. 驗收與下一輪優先順序

本輪測試包括 AIC News／research／signal 245 項、Break News／Nexus／launcher 91 項、Broker 全套 1,237 項及 ruff／mypy；集合存在重疊，不能直接加總。最後一次發布順序修正後，38 項研究測試通過。面板另有 2 項 Node 行為契約，轉義正控制能重現失敗；錯誤 token、重複 execution 與發布被新事件阻擋也有會失敗的案例。

正式 8080 的 invest／earnings／momentum／nexus API 收尾皆回 HTTP 200，PTC 可讀、每次最多三張且標記 exploratory。六頁已接面板。可控瀏覽器視窗不可用，因此沒有聲稱完成桌機／手機目視驗收。版本三處同步為 4.140.0。既有今日 DIGEST 缺席及三筆 Nexus packet digest 過期未被改寫成成功；本任務沒有觸發正式 DIGEST 或圖譜晉升。

**判斷：可使用這版收集、查閱與追蹤探索資訊；先不要提高呼叫上限。** 對帳可靠性已實測，包括成功、失敗、延遲 ACK、忙碌恢復及 quota 停止；token 完整性仍有兩筆未知。研究價值目前主要是拆清證據與缺口，不是新的投資結論。

1. 優先補「高影響事件的公司／監管第一手文件」，並分別量測取得率與實際引用率。
2. 修復或替換本輪反覆失敗的 BLS、Futu、Social 路徑；保持錯誤與無新發布分開顯示。
3. 在真實財報／經濟發布時段補 filing、calendar、followup 覆蓋；每次仍先保留 Broker 額度。
4. 先量測 native 呼叫約 19.7k input 的組成，再判斷如何縮小上下文；目前不能把全部 input 歸因於新聞包。
5. 保留單模型 A/B 的標示，獨立複核只用在高影響且未解決的主張，避免為形式上的辯論增加成本。
